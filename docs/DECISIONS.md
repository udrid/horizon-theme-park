# Decisions

Every design choice you approve is recorded here so nobody asks twice.

| # | Choice | Reason | Date |
|---|---|---|---|
| 1 | Tree felling is dropped entirely. | Focus on one project. | 2026-10-30 |
| 2 | Aim at theme parks from day one ("option C"): repo `horizon-theme-park`, room for `coasters/`, `rides/`, `park/`. Milestone order unchanged; the coaster is still the first showcase. | Cheapest change, keeps the research done, gives the project a park-sized name now. | 2026-10-30 |
| 3 | Crates are named `park-core`, `park-sim`, `park-web`. Coaster code will be a module inside `park-core`. | A park with several ride types does not fit in a crate called "coaster". | 2026-10-30 |
| 4 | Project folder is `horizon-theme-park`, next to the other Horizon folders on the Desktop. | Everything stays together and is easy to find. | 2026-10-30 |
| 5 | Tests and builds run mostly on your own computer. CI on GitHub is the free backup check. The Codespace file stays in the repo but is optional. | You have unlimited internet; the only limit is AI usage, and running commands locally lets the agent fix problems without copy-and-paste. | 2026-10-30 |
| 6 | Cargo for our own tests comes from official rustup (Rust 1.99.1, MinGW/`gnu` target, minimal profile), not the launcher's toolchain. Its folders are added to PATH per command, not permanently. | The launcher's `rust install` left no rustc or cargo. The launcher's MinGW linker works, and there is no Visual Studio. | 2026-10-30 |
| 7 | The game door is option B: `host_cmd` (console commands through `native_run_command`, hook API 21, merged in horizon#4610 on 2026-10-30) is the main path. `host_mixin` is a pinned fallback, used only for jobs the engine spike shows commands do badly, and it is the only file allowed to call Horizon's private code. Both sit behind one `Host` trait, plus a fake host for tests. | Stable commands survive Horizon updates; the fallback is a safety net if commands prove too slow or too limited. | 2026-10-30 |
| 8 | `park-core` reaches the game as one glued file, made by a small Rust tool in our workspace (`tools/park-bundle`). CI fails if the glued file is stale. `park-core` uses only libraries Horizon already has, at Horizon's versions. | A native mod can carry only `.rs` files, not its own libraries; a Rust tool keeps the repo to one language and runs with the Cargo we already have. | 2026-10-30 |
| 9 | `park-core` uses `glam` 0.30.10 (Horizon's exact version) with f64 types (`DVec3`, `DQuat`) for all positions and directions. | Well-tested maths shared with Horizon; f64 avoids jitter on tracks far from spawn and matches Horizon's entity positions. | 2026-10-30 |
| 10 | Layout option B: `park-core` holds the coaster maths (`coaster/`), the `Host` trait and `FakeHost` (`host.rs`), the command-text writer (`commands.rs`), the per-tick loop (`runtime.rs`) and saving (`save.rs`). The native mod holds only the glued `park.rs`, a thin `glue.rs` and the fallback `host_mixin.rs`. `rides/` and `park/` folders are added at M7, not before. | Almost everything, including exact command text and tick order, is tested by `cargo test` without a game build, and Horizon updates touch about 100 lines. | 2026-10-30 |
| 11 | Units: blocks (1 block = 1 m), seconds (1 tick = 0.05 s), blocks/s (shown as km/h), radians in code and degrees in saved files and commands. Gravity is real, 9.81 blocks/s², times a per-coaster `gravity_scale` (default 1.0). G-forces are always reported in real g. | Real layouts behave like real coasters, readouts stay honest, and the dial lets you tune feel without code changes. | 2026-10-30 |
| 12 | Integrator: semi-implicit Euler (update speed first, then move with the new speed) with a fixed 10 substeps per 20 Hz tick (dt = 0.005 s). Required tests: a frictionless closed loop keeps its speed within 1% after 100 laps, and two runs of one coaster give identical numbers. | Simple to read, does not invent energy, copes with sudden brake and lift changes, and fixed steps make every ride repeatable. | 2026-10-30 |
| 13 | A multi-car train is one rigid body along the track: one `s` (front car) and one `v`; car i sits at `s - i * spacing`. Gravity is summed over every car on its own slope. All cars weigh the same. A lift or brake acts on the whole train when any car is on it. | Gives the real "creep over the top, then rush" feel and the back-row yank, with no risk of cars separating, and stays simple to check. | 2026-10-30 |
| 14 | Losses each substep: rolling friction `mu * g * |normal g|` plus air drag `k * v^2`, both against the motion. Defaults per coaster: mu = 0.015, k = 0.0015 per block (about 18% speed lost over 100 flat blocks at 20 blocks/s). | Realistic: tight valleys and loops cost more speed and airtime hills less, and it reuses the g-force we compute anyway. | 2026-10-30 |
| 15 | G-forces come from the track's shape: curvature from the change in direction over ±0.25 block in the arc-length table, acceleration = (dv/dt) along the track + v² × curvature, felt push = (acceleration - gravity) / 9.81 split into vertical, lateral and longitudinal on the car's frame. The HUD shows a 0.25 s average; ride stats keep raw peaks. Measured at the rails until M5 adds the heartline (about 1.1 blocks above the rails). | Exact and repeatable for any speed, testable by hand (radius 10 at 10 blocks/s gives 1.02 g), and usable in park-sim and the browser before anyone rides. | 2026-10-30 |
| 16 | Riders sit on invisible seat displays, separate from the car model display. Each seat is moved every tick to the car's frame plus its own seat offset; 2 seats per car by default, set per coaster. The spike tests riding the car display directly first (quickest proof), then seats. | Several riders per car, seat height can follow the heartline, and car models stay simple; costs only a few extra `tp` commands per tick. | 2026-10-30 |
| 17 | Track rails are drawn with one display entity every 1 block (spacing stored per coaster, so it can change later). Entities are used only for things that must be smooth or must move: rails, cars and seats. Supports, stations, queues and decor are ordinary blocks from the content mod. Car and seat moves use `teleport_duration` (spike picks 1, 2 or 3). | Smooth curves with the simplest code; blocks cost no entities and players can place them. | 2026-10-30 |
| 18 | Requirement: a whole theme park packed with rides and decorations must be viewable and playable at once. Every rendering and budget choice is judged against this, and the engine spike must measure it. | Your goal for the project: a full park, not one showcase ride. | 2026-10-30 |
| 19 | The mod parks far-away rides: a ride with no player within 128 blocks has its displays removed, and they are redrawn when a player comes within 112 blocks, about 50 per tick. Parked rides keep simulating. The entity budget counts displays near each player (the spike sets the real number; first guess 2,000–3,000), not a world total. The spike adds a "packed park" test: 6,000 displays over 400 × 400 blocks. | The server only carries rides near players, so a packed park can grow; the save file stays the single true copy of the track. | 2026-10-30 |
| 20 | Saving: one pretty-printed JSON file per ride in `<world>/horizon-theme-park/rides/<id>.json`, plus `park.json` for park settings and the ride list. Every file has a `"format"` version. Writes go to `.tmp` then swap in, keeping a `.bak`. Save right after a change and when the world closes. A file with a newer format than the mod knows is never overwritten. On world open the mod removes its own tagged displays (tag `htp`) and redraws from the files. Trains start in the station when a world opens. | One damaged file loses one ride, not the park; single rides are easy to share and load into the browser designer; the files are the one source of truth. | 2026-10-30 |
| 21 | Everything runs once per tick at `ServerTickEnd`, in this order: (1) mod on and world running, (2) apply queued orders, (3) read players: nearness, seats, safe teleport, (4) physics, 10 substeps per ride, (5) park and unpark rides (at most 50 pieces drawn per tick), (6) move cars and seats near players, (7) particles and HUD values, (8) save if changed. At most 400 commands per tick; extra ones wait for the next tick, with a log warning. The loop lives in `park-core/src/runtime.rs`. | Players have already moved, so we see where they really are; moves go out with this tick's update; one hook, testable with the fake host. | 2026-10-30 |
| 22 | Riding: the rider's view stays free (the car does not turn it). A rider who gets off mid-ride is let go where they are, keeping the seat's velocity, and normal Minecraft gravity takes over, so at speed they go flying. How the velocity is given is for the spike to find (risk R9); if no command can do it, it is a job for the fallback `host_mixin` (asked before building). | Owner's choice: getting off should feel physical, not be a magic teleport. | 2026-10-30 |
