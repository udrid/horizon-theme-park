## 1. Goal, in plain words

You build your own coaster. With a track wand you click points into the world; particles show the curve as you go.
`/coaster create thunder` turns the points into a ride, with a report on how it would feel (g-forces, top speed,
airtime) using the realism limits (D58). Rides are saved, so they're still there after you quit and come back.
Far-away rides are packed away and redrawn when you walk up (D30).

## 3. How building works (recommended answers)

```
 1. /coaster wand            → you get the track wand (htp:wand, a content-mod item)
 2. right-click a block      → a node appears 1 block above it (centre of that block); a small marker
                               shows it, and particles draw the curve so far (for 30 s, F3)
    sneak + right-click      → removes the last node
    right-click the air      → changes the wand's mode: track → lift → brake → station
                               (the action bar shows it; the mode is stored on the node you place next,
                               and applies to the track from that node to the next one)
 3. /coaster create <name>   → the nodes become a closed ride (last node joins the first), saved to
                               <world>/horizon-theme-park/rides/<name>.json (D20). Chat shows its
                               realism report (C3). The train appears in the station (D20).
 4. /coaster edit <name>     → its nodes go back to your wand to change; create again to save
```

Ride files are the only true copy (D20). The world's blocks hold nothing about a ride, so nothing can get out of step.

## 5. Tests (park-core, no game)

1. Save → load gives an equal ride (nodes, elements, settings, train layout).
2. A file with a newer `format` is refused, left untouched, and the player is told.
3. A leftover `.tmp` from a crash is ignored; the `.bak` survives a failed write.
4. A broken JSON file loses only that ride; the others load.
5. Wand: clicks add nodes 1 block above the clicked block's centre; sneak-click removes the last; modes cycle.
6. `create` refuses fewer than 4 nodes, no station, or two nodes closer than 1 block, with a clear message.
7. `create` with a name that exists asks for `edit` instead (no silent overwrite).
8. Realism report: the M2 demo passes every limit; a sharp hand-made track fails lateral g with the right numbers.
9. On world open: one `kill` per session tag, then rides drawn near players only.
10. Orders queued in the item hooks run on the next tick, in order.
11. Parking: when the last player goes past 96 blocks, `FakeHost` sees that group's displays removed; within 80, redrawn at most 50 a tick.
12. A redraw bumps the generation; old-generation entities found near a player are removed.
13. Two rides, two players far apart: counts never exceed D27's 1,500 near either player.

## 6. Choices for you

**C1. How you place track.**
- **A. Wand clicks: right-click a block and a node appears 1 block above it.** Nodes live only in the ride file, so
  nothing in the world can get out of step. For tall track, stand on (or click) blocks you place as scaffolding, then
  remove them. Like the editor in TC-Coasters (an MIT-licensed coaster plugin). **Recommended.**
- B. Track-node blocks you place in the world, linked in order with the wand. Feels like placing rails, but breaking or
  moving a block has to update the ride, and other players can break them.

**C2. How you set lift, brake and station.**
- **A. Wand modes: right-click the air to switch track / lift / brake / station.** The mode goes on the next node you
  place. The action bar shows the mode. **Recommended.**
- B. A command per node: `/coaster set node 5 lift`.

**C3. Realism check on your own coasters (D58).**
- **A. A report in chat after every `create`:** top speed, max g, lateral g, airtime, drop angles; anything past D58's
  limits shown in red, with where it happens. You can still ride it (it's your coaster). **Recommended.**
- B. Refuse to open a ride that breaks a limit.
- C. No check.

**C4. Track rules on `create`.**
- **A. At least 4 nodes, exactly one station stretch, no two nodes closer than 1 block; the track always closes into a
  loop.** **Recommended.**
- B. The same, but also allow open (shuttle) tracks. Needs a train that reverses: later.

**C5. Commands.**
- **A. `/coaster wand`, `create <name>`, `edit <name>`, `delete <name>`, `list`, `set <name> cars <1–8>`, plus `demo`
  and `remove` from before. Everyone can use them** (single-player and LAN friends). **Recommended.**
- B. The same, operators only.

### Small choices (I'll use these unless you say otherwise)

- **S1.** Ride names: lowercase letters, digits and `-`, up to 32 characters (also the file name, ARCHITECTURE §3).
- **S2.** The preview: `end_rod` particles every 0.5 block, redrawn every 10 ticks, only for the player who clicked,
  for 30 s after their last wand use (F3). Node markers are small displays, removed when the session ends.
- **S3.** `/coaster delete` asks you to type it twice within 10 s, and keeps the file as `<name>.json.deleted`.
- **S4.** Every entity gets a session tag `htp_s<n>` (a number stored in `park.json`, bumped at each world open). Near
  each player, every 5 s: `kill @e[tag=htp,tag=!htp_s<n>,distance=..128]` clears leftovers from unloaded chunks (F6).
- **S5.** Settings per ride, saved in its file: cars (default 3, D55), speeds and dwell from D57, friction and drag
  from D14. Only `cars` has a command in M3.

## 8. Risks

- **A crash while saving:** the `.tmp` / `.bak` swap (D20) and test 3 cover it.
- **Leftovers from unloaded chunks** (F6): S4 handles them; it costs one scan per player every 5 s.
- **Selector cost** (D25) grows with entities, and several rides mean more. Parking (D30) keeps the count near each
  player down; the real fix is still Horizon's UUID lookup (#4966) or private code.
- **Building tall** with click-on-a-block needs scaffolding. If it's annoying in practice, a later "node height" key
  can be added.
- **`native_world_dir()` timing** (F5) is read, not tested: T0 checks it.
