# Architecture

How Horizon Theme Park is built. Every choice here was approved by the owner and is logged in
[DECISIONS.md](DECISIONS.md) (numbers in brackets, like [D12], point there). Items marked **OPEN**
are not decided yet: ask the owner before building them (see [WORKING_WITH_ME.md](WORKING_WITH_ME.md)).

Checked against Horizon main `073afd48` (hook API 19) and PR horizon#4610, merged 2026-10-30 as
**hook API 21** (`native_run_command`, `native_action_bar`, `native_acting_player`,
`native_right_click_block`). The mod needs `"hooks": 21`. The local `../horizon` clone predates the
merge; updating it is a download, so ask first.

---

## 1. The big picture

```
 the game (Horizon)                         our code
 ─────────────────                          ────────
 native_server_tick ──▶ glue.rs ──▶ park-core::runtime::tick(&mut host)
 native_perform_command ─▶ glue.rs ──▶ runtime.queue(order)      (never runs commands here)
                                              │
                                              ▼
                         Host trait  ──▶ HostCmd: command text ──▶ native_run_command
                                     └─▶ HostMixin (fallback, private calls, pinned)
                                     └─▶ FakeHost (tests: records every call)
```

- **`park-core` is the brain.** Pure Rust, no Horizon. It holds the maths, the per-tick loop and even
  the exact command text, so almost everything is tested by `cargo test` in seconds [D10].
- **The native mod is paper-thin.** It forwards hooks to `park-core` and hands command strings to the
  game [D7, D10].
- **Rendering = display entities**, only for things that must be smooth or move (rails, cars, seats).
  Everything else is ordinary blocks [D17].

### Rules for code inside `park-core` (so the glue tool works)

1. No dependencies except `glam` 0.30.10, `serde`, `serde_json` at the versions in Horizon's
   `Cargo.lock` [D8].
2. Modules refer to each other as `crate::coaster::…`. `park-bundle` rewrites `crate::` to the path
   of the glued module inside Horizon. No `#[path]` attributes, no `include!`, no `build.rs`.
3. No global mutable state (`static mut`, `thread_local!`). All state lives in `Runtime`.
4. No `std::time`, no randomness, no threads. Time only ever comes in as `dt` [D12].
5. File access only in `save.rs`, through paths the caller passes in.
6. `park-bundle --check` fails CI when `park.rs` is stale.
7. **No file attributes** (`#![…]`). Horizon's mixin tool refuses them, and it counts `//!` comments as file
   attributes too. `//!` comments are still fine in park-core, because `park-bundle` turns them into `//`.
   Crate-wide lint settings go in park-core's `Cargo.toml`.
8. **No `env!`, `option_env!`, `include!`, `include_str!`, `include_bytes!`, `#[macro_export]` or
   `extern crate`.** In the game, `env!("CARGO_PKG_VERSION")` would quietly return Horizon's version, and an
   exported macro would leak out of our module.
9. **Declare modules on one line** (`mod name;` or `pub mod name;`, attributes on the lines above), with the
   file at `name.rs` or `name/mod.rs`. Inline `mod name { … }` blocks are fine, but must not contain a
   `mod x;` line.
10. **Turn on no library feature Horizon lacks.** Horizon's `glam` has no `serde` support, so a `DVec3` can't
    be saved by `serde` directly. Saved files use plain arrays like `[f64; 3]`. The M3 plan designs those
    file types.
11. **Never write `crate::` inside a text string**, because `park-bundle` would rewrite it.

`park-bundle` refuses 7 and 8 and reports a missing or doubled module file (9). The compile test
(`tools/park-bundle/tests/glued.rs`) and edition 2024 catch much of the rest.

## 3. Data model (Rust types; bodies are for the builder)

Units everywhere [D11]: blocks (1 block = 1 m), seconds, blocks/s, radians in code, degrees in
saved files and commands. Vectors are `glam::DVec3`, rotations `glam::DQuat` (f64) [D9]. World up is
`+Y`. Minecraft is right-handed: facing east (+X) with up +Y, your right hand points south (+Z).

```rust
// coaster/spline.rs
pub struct TrackNode {
    pub pos: DVec3,          // where the rail passes, in world blocks
    pub roll: f64,           // bank angle in radians (degrees in the file), + = right side down
    pub kind: Element,       // what the track does from this node to the next
}
pub struct Segment {         // the curve between node i and node i+1 (derived, never saved)
    pub from: usize,         // node index
    pub ctrl: [DVec3; 4],    // cubic Bézier control points
    pub roll: [f64; 2],      // roll at start and end
    pub length: f64,         // blocks
}

// coaster/mod.rs
pub struct Track {
    pub nodes: Vec<TrackNode>,
    pub closed: bool,        // last node joins the first
}
pub struct TrackGeometry {   // built from a Track; rebuilt after every edit
    pub segments: Vec<Segment>,
    pub table: ArcTable,
}

// coaster/table.rs
pub struct ArcTable {
    pub step: f64,           // 0.1 block between samples
    pub length: f64,         // total track length
    pub samples: Vec<ArcSample>, // samples[i] is at s = i * step
}
pub struct ArcSample {
    pub segment: usize,
    pub frame: Frame,        // already includes roll
    pub element: Element,
}

// coaster/frame.rs
pub struct Frame {
    pub pos: DVec3,
    pub forward: DVec3,      // unit, along the track
    pub up: DVec3,           // unit, out of the top of the rails (after roll)
    pub right: DVec3,        // unit, forward × up
}

// coaster/elements.rs
pub enum Element {
    Normal,
    Station { dwell: f64 },              // seconds held before dispatch
    Lift { speed: f64 },                 // chain speed, blocks/s
    Brake { target_v: f64 },             // trims down to this speed, blocks/s
    BlockBrake,                          // ends a block section; stops the train if the next is taken
    Booster { force: f64 },              // extra acceleration, blocks/s²
}

// coaster/mod.rs
pub struct Train {
    pub cars: u32,
    pub spacing: f64,        // blocks between car centres
    pub s: f64,              // front car, blocks along the track
    pub v: f64,              // blocks/s, + = forward
    pub state: TrainState,
}
pub enum TrainState { InStation { held: f64 }, Running, Held }
pub struct Section { pub start: f64, pub end: f64, pub occupied_by: Option<usize> }
pub struct Stats {           // filled by a test run (park-sim) or live
    pub length: f64, pub max_height: f64, pub max_speed: f64, pub ride_time: f64,
    pub g_vertical: [f64; 2], pub g_lateral: [f64; 2], pub g_longitudinal: [f64; 2], // [min, max]
    pub airtime: f64, pub inversions: u32,
    pub ratings: Option<Ratings>,        // M5, formulas OPEN
}
pub struct Settings {
    pub gravity_scale: f64,  // 1.0 [D11]
    pub friction: f64,       // mu = 0.015 [D14]
    pub drag: f64,           // k = 0.0015 per block [D14]
    pub track_spacing: f64,  // minimum piece length, 1.0 block; pieces stretch up to 4 blocks on gentle track [D17, D29]
    pub seats_per_car: u32,  // 2 [D16]
    pub seat_offsets: Vec<DVec3>, // in car frame: (right, up, forward)
    pub teleport_ticks: u8,  // car move interval k: about 5 on gentle track, 1–2 on tight curves [D26, D32].
                             // The M1 plan decides whether this is a setting or worked out from the curve
}
pub struct Coaster {
    pub id: String,          // lowercase letters, digits, '-' (also the file name)
    pub track: Track,
    pub trains: Vec<Train>,
    pub sections: Vec<Section>,
    pub stats: Stats,
    pub settings: Settings,
}
```

### Curve choice [D42]

Centripetal Catmull-Rom through every node, converted to Bézier segments (`Segment` stores the four control points). Decided at M1.

### Arc-length table and frames

1. Sample each segment at 64 points per block of chord length. Add up the distances to get `s` at
   each sample.
2. Resample at a uniform `step` = 0.1 block, so `s → sample` is one division plus a blend between
   two neighbours (no searching).
3. **Rotation-minimising frames** (parallel transport): start with `up` = world up projected off
   `forward` at s = 0. At each next sample, rotate the previous `up` by the smallest rotation that
   takes the old `forward` to the new one. Never use Frenet frames: they flip where the bend changes
   side.
4. **Closed tracks:** after one lap, `up` may not match its start (a twist). Measure that angle and
   spread its correction evenly over the lap.
5. Apply roll: blend the node rolls along s (smoothstep between nodes), and rotate `up` and `right` about
   `forward`.
6. Heartline (M5): rider position = `frame.pos + frame.up * heartline` (1.1 blocks) [D15]; the
   rails are offset so the heartline is the smooth path. Until M5, heartline = 0.

## 4. Physics [D11–D15]

One train is one rigid body: one `s`, one `v` [D13]. Car *i* is at `s_i = s − i·spacing` (wrapped if
closed). Gravity `G = 9.81 × gravity_scale`. Ten fixed substeps per tick, `dt = 0.005 s` [D12].

Each substep, for each train:

```
for each car i:  f_i = table.frame_at(s_i)
                 K_i = (forward(s_i + h) − forward(s_i − h)) / (2h)      h = 0.25 block   [D15]
                 A_i = a_prev · f_i.forward + v² · K_i                    (rider acceleration)
                 F_i = A_i − (0, −G, 0)                                    (push the seat gives)
                 N_i = |F_i − (F_i · f_i.forward) f_i.forward|             (normal push, blocks/s²)

a_gravity  = −G · mean_i(f_i.forward.y)                                    [D13]
a_friction = −sign(v) · friction · mean_i(N_i)                             [D14]
a_drag     = −sign(v) · drag · v²                                          [D14]
a          = a_gravity + a_friction + a_drag
a          = element changes to a (below)
v = v + a·dt                    ← speed first
apply element limits to v (lift/push/wheels pull, brake floor, no rolling back on the lift)
s = s + v·dt                    ← then position with the NEW speed (semi-implicit Euler)   [D12]
wrap s; if the front car reaches the station's stop point, snap there and hold
```

- `a_prev` is the previous substep's actual speed-up `(v_after − v_before)/dt`, element effects included.
- At very low speed (`|v| < 0.05` with `|a_gravity|` under the friction limit), set `v = 0`, except on the lift and in the station.
- Level frames (D59): on unbanked track "up" is the sky projected square to the track (`Table::new_level`).
- Felt g per car, reported in real g [D11, D15]: `g = F_i / 9.81`, split into
  `vertical = g·up`, `lateral = g·right`, `longitudinal = g·forward`. At rest on flat track that
  gives vertical = +1.0 (× gravity_scale).
- The HUD shows the rider's car averaged over the last 0.25 s (5 ticks). `Stats` keep raw peaks.

### Elements [D57]

"On an element" means any car of the train is on it [D13]. Numbers are the approved ones [D57].
Pulling elements accelerate at `ELEMENT_ACCEL = 1.5 blocks/s²` (about 0.15 g) and never jump the speed.

| Element | Behaviour | Default |
|---|---|---|
| Station | The front car follows a slowing curve `v = √(2·1.0·distance)` (between 0.05 and 3 blocks/s; slower trains are pulled along) and stops exactly at the stop point. It holds there. When someone sits, a 5 s countdown starts (cancelled if everyone leaves); then it pushes out up to the push speed. A station stretch must not cross the lap's start (`Course::validate`). | dwell 5 s, push 2 blocks/s |
| Lift { speed } | If `v < speed`: pull up to `speed` at `ELEMENT_ACCEL`, first cancelling gravity and friction. Holds `speed` against gravity and never lets the train roll back (`v ≥ 0`). A train already faster just coasts. | 5 blocks/s (18 km/h) |
| Brake { target_v } | If `v > target_v`: `a −= brake_decel` until `v ≤ target_v`. A brake only removes speed, so on real track the train may keep slowing below the target. Brakes do not stack with the station's curve. | decel 6 blocks/s², target 3 blocks/s |
| BlockBrake | (M4) If the next section is taken: stop and hold (`Held`). Else act as a trim brake. | pass 3 blocks/s |
| Booster { force } | (M4) `a += force` | 8 blocks/s², no speed cap (OPEN) |

### Required tests (park-core, no game)

1. Frictionless closed loop: speed within 1% of the start after 100 laps [D12].
2. Same ride run twice: identical `s` and `v` at every tick (deterministic) [D12].
3. Frictionless 40-block drop from rest: bottom speed `√(2·9.81·40) = 28.01` blocks/s, ±0.5%.
4. Flat unbanked circle, radius 10, 10 blocks/s: lateral 1.02 g, vertical 1.00 g, ±1%.
5. Flat straight, 20 blocks/s, default friction and drag: about 18% speed lost over 100 blocks
   (16.46 ± 0.1 blocks/s at the end; worked by hand from `ds = −v dv / (μG + k v²)`).
6. 6-car train cresting a hill: the back car's speed at the top is greater than the front car's was
   (asymmetric hill; test 13 is the same effect on the demo's lift crest).
7. Frames: no flip through an S-bend; a closed loop's `up` matches its start within 0.1°.
8. Lift: never rolls back, pulls up gently, leaves at the chain speed.
9. Brake (frictionless track): leaves at `target_v` ± 0.1.
10. Station: stops within 0.2 of the stop point, holds for the dwell, pushes out gently.
11. Demo lap: never stalls (except in the station) and ends in the station; nothing jolts
    (acceleration at most 15 blocks/s², forward/back push at most 1 g).
12. Demo limits (D58): drops 50–65°; valleys at most 4 g; airtime between 0 and −0.5 g; sideways at most 1 g;
    vertical g changes by at most 3 g over any 1-second window; top speed at most 30 blocks/s; lift 20–30 blocks.
13. Back row over the lift crest is clearly faster than the front row was (D13).

## 5. The Host trait: the only door to the game [D7, D43]

`Host` has four methods (`players`, `run(command) -> bool`, `broadcast`, `tell`) plus `log` (default: nothing).
Anything private is added later as one more method with a "not available" default, so this stays the only door.
All command text lives in `commands.rs` as pure functions, tested word for word:

| Job | Command |
|---|---|
| rail piece | `summon minecraft:item_display X Y Z {Tags:["htp","htp_demo"],item:{id:"htp:rail",count:1},transformation:{…}}` |
| car | the same with `htp:car`, `Rotation`, `teleport_duration` *k*, tag `htp_car_demo_0` |
| move car | `tp @e[tag=htp_car_demo_0,limit=1] X Y Z yaw pitch`, every *k* ticks, aimed *k* ticks ahead [D32, D44] |
| seat | `summon minecraft:minecart …` with tag `htp_seat_demo_<i>` (a minecart per seat; one line in `commands.rs` switches the kind) [D49] |
| move seat | `tp @e[tag=htp_seat_demo_<i>,limit=1] X Y Z yaw pitch`, every tick, ridden or not |
| remove | `kill @e[tag=htp_demo]`; at world open `kill @e[tag=htp]` [D20] |

Players board by their own right-click, since the console cannot mount them [D48]. Commands never run inside the
command hook: orders are queued for the tick [D21]. `FakeHost` records the strings in order.

## 6. Rendering [D16, D17, D19]

- **Rails [D29]:** adaptive pieces: up to 4 blocks long while the track is straight or bends gently, 1 block
  where it bends more than a set angle (`track_spacing` is the minimum length). Each is an `item_display`
  showing `htp:rail` from the content mod, rotated by the frame's quaternion and stretched to its length along
  forward. Rails are placed once and never moved. Check in game: how a stretched model looks.
- **Cars:** one `item_display` per car showing the `htp:car` shell, moved every *k* ticks (*k* from 1 to 5, worked out once per ride from the tightest bend and speed [D44]).
- **Seats:** one minecart per seat, hidden inside the shell, moved every tick by its tag [D49]. A rider hangs 1.2125 blocks below the seat (measured), so "rider on" means a player within 1.0 block of that point and "off" means beyond 2.0. The rider's camera steps 20 times a second [D23].
- **Blocks, not entities:** supports, stations, queues and decor are content-mod blocks [D17].
- **Parking [D19, D30]:** the track is split into groups of about 16 pieces. A group with no player within
  96 blocks (3D distance) has its displays removed; a player within 80 blocks gets it redrawn, at most 50
  pieces per tick. Physics keeps running while parked. A redraw bumps the group's "generation", so UUIDs
  never repeat. Check in game: pop-in margin at speed (80 blocks vs the 64-block draw range).
- **Budget [D19, D27]:** the first budget is **1,500 displays within 160 blocks of each player**, and no more than
  about 2,000 in the world at once until commands get cheaper.
  Past it, the mod warns in chat and won't unpark more rides near that player.
- **Free view, fling-off dismount [D22]:** the rider's view is never turned by the car. A rider who
  gets off mid-ride stays where they are and keeps their seat's **true velocity**:
  `seat_velocity = v · (seat_pos(s + 0.05) − seat_pos(s − 0.05)) / 0.1`, where `seat_pos(s)` is
  the car frame at `s` plus the seat offset. With no track pushing on them any more, they carry
  straight on while the track bends away: outward on a corner, up and over on a fast crest. Normal
  Minecraft gravity takes over; no extra kick. Sent through `Host::launch_player` in blocks/s
  (converted to blocks/tick for the game) (risk R9). In the station, getting off is a normal dismount.
  Two things the spike must measure: Minecraft slows a flying player with its own air drag (about 9%
  of sideways speed per tick), so throws are shorter than in real life; and the game caps a sent
  velocity at about 3.9 blocks/tick (78 blocks/s).

## 7. Saving [D20]

```
<native_world_dir()>/horizon-theme-park/
   park.json                {"format":1, "rides":["thunder-run", …], "settings":{…}}
   rides/<id>.json          {"format":1, "id":…, "closed":true, "settings":{…}, "nodes":[{"pos":[x,y,z],"roll":deg,"kind":{…}}], "trains":[{"cars":6,"spacing":2.2}]}
```

- serde JSON, pretty-printed. Only `Track`, `Settings` and train layout are saved. Geometry, sections
  and stats are rebuilt on load. Trains start in the station.
- Write `<file>.tmp`, keep the old one as `<file>.bak`, then rename `.tmp` over the file.
- `format` newer than the mod knows: refuse to load that ride, tell the player, never overwrite.
  Older: upgrade step by step in `save.rs` (`v1 → v2 → …`), each step tested with a stored sample
  file.
- On world open: `remove_tagged("htp")`, then draw from the files.

## 8. The tick loop [D21]

All at `ServerTickPhase::ServerTickEnd`, in `Runtime::tick(&mut self, host: &mut impl Host, dt: f64)`:

1. Skip if the mod is off (`native_on`) or the world isn't running.
2. Apply queued orders (commands, wand clicks).
3. Read `host.players()`: nearness per ride, who is in which seat. A seated rider more than 2 blocks
   from their seat counts as off: outside the station, `launch_player` with their seat's velocity [D22].
4. Physics: every ride, 10 substeps (section 4).
5. Park and unpark rides; draw at most 50 displays.
6. Move cars and seats of unparked rides.
7. Particles (build preview) and HUD values.
8. Save the rides that changed.

At most 400 commands per tick. The rest carry over, with one log warning per ride per minute.
