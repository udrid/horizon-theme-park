# Horizon Theme Park: rules for every agent

A roller coaster and theme park mod for Horizon (Minecraft 26.3 in Rust). Read this first, then
[docs/WORKING_WITH_ME.md](docs/WORKING_WITH_ME.md) (the full rules; it wins any conflict).

## 1. Working with the owner (most important)

- **The owner is a beginner** with little to no coding experience and wants to learn. Teach as you
  go: before each step, say what and why in one or two plain sentences; after it, say what changed
  and how they can see it. Explain every new term with an everyday comparison and add it to
  [docs/LEARNING.md](docs/LEARNING.md). Short sentences, numbered steps, few terms.
- **Research and test before any build or download, and build only after their "yes".** Order:
  read docs and code, then cheap `cargo test` on `park-core`, then a game build. Before anything that
  downloads or builds, state what it is, why now, the data size, the time, where it runs, and
  whether it could wait. Then stop and wait.
- **Every design choice goes to the owner first.** That covers architecture, file layout, formats,
  physics formulas and constants, how players build or ride, names, dependencies, private Horizon code,
  and edits to `docs/ARCHITECTURE.md` or `docs/DECISIONS.md`. Give 2–3 options with trade-offs and a
  recommendation, then wait. Never build it "for now".
- Approved choices go into [docs/DECISIONS.md](docs/DECISIONS.md) with a number and date. **Never
  re-argue a recorded decision**; if you think one is wrong, say why and ask.
- Commands for the owner: one at a time, what it does, and what they should see.
- End each session with **"What you learned today"** (3–5 bullets and one optional exercise).
- Don't bring up Veinminer: it was dropped from the plan.

## 2. House rules

- Never push, post to GitHub or Discord, sign in, or run `--trust-native-code`. Prepare it and
  explain it; the owner does it. Draft messages instead of sending them.
- Never commit Mojang files or Horizon's `.local/`. Follow `../horizon/AGENTS.md` "Rules that bite"
  (scratch `HORIZON_HOME` for any game run; never the owner's real saves).
- Licences: Horizon and TC-Coasters are MIT (learn and port, with credit). OpenRCT2 is GPL-3: ideas
  only, never its code.
- `park-core` stays game-free. Its only dependencies are `glam` 0.30.10, `serde`, `serde_json` at
  Horizon's versions. Rules for code in it: [ARCHITECTURE.md §2](docs/ARCHITECTURE.md).
- Stable hooks only (we need hook API 21). Private Horizon calls go only in `host_mixin.rs`, and only
  after the owner approves.
- Never edit `mods/native/mixins/horizon-theme-park/park.rs` by hand. It's generated by
  `tools/park-bundle`.
- **Pause and ask before reading a large part of Horizon** (more than about 2,000 lines). Write the
  exact question for the free reader instead, and wait for the owner to paste its answer.
- Comment code so a beginner can follow what each part does. Small commits, each with tests.

## 3. Build and test

Rust is official rustup 1.99.1, `gnu` target. Add it to PATH **per command**, never permanently
(PowerShell):

```powershell
$env:PATH = "$env:USERPROFILE\.cargo\bin;$env:APPDATA\horizon-launcher\rust\1.99.1-x86_64-pc-windows-gnu\mingw64\bin;$env:PATH"
cargo test --workspace          # all tests, seconds, no game needed
cargo clippy --workspace --all-targets -- -D warnings
cargo fmt --all
cargo run -p park-bundle              # re-glue park.rs after changing park-core
cargo run -p park-bundle -- --check   # is park.rs up to date? (exit code 1 = stale)
```

Game build: **only the owner runs it**, after saying yes (the first build took 520 s on 2026-10-31 and downloaded Horizon's source once; more if Rust
needs downloading):

```powershell
# The launcher is not on PATH. It sits one folder above the repo, so run this from the repo folder:
..\horizon-launcher.exe native-build mods\native\mixins\horizon-theme-park --trust-native-code
```

CI (`.github/workflows/ci.yml`) runs fmt, clippy and tests on every push. It's the free backup check.

## 5. Which model does what

| Who | Job |
|---|---|
| **Claude Opus 5.5** | Plans each milestone (`docs/milestones/Mx.md`), architecture, reviews physics and maths, hard bugs |
| **Claude Sonnet 5.5** | Builds: code and tests, following the milestone plan |
| **Claude Haiku 5.5** or a free model | Data, JSON (blocks, models, recipes), docs, boilerplate tests, changelogs |
| **Antigravity CLI (`agy`)** | Free bulk reading of big Horizon files (it replaced Gemini CLI, whose free tier ended). Weekly allowance. |
| **The owner** | Every design choice, every build and download "yes", every `--trust-native-code`, every post, the videos |

A milestone runs: Opus plans → the free reader answers big reading questions → the owner approves
choices → Sonnet builds with tests → second opinion on the diff → Opus review if physics or
architecture changed → the owner builds, plays and records.

**Sessions talk to each other directly.** Send status, questions and review requests with `SendMessage` to the
other session's id (the planner that started you, or the builder it started). Never write a paste-ready note for
the owner to carry between sessions. Design choices still go to the owner, asked in your own session.
